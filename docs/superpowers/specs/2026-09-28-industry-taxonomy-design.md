# A股行业分类树设计

> 状态：待评审（已按 2026-09-28 review 修订）  
> 日期：2026-09-29  
> 范围：仅 A 股行业导航/归属树；不含温度/RS 公式、ETF 树细节、回测引擎

## 1. 目标

为趋势扫描工具提供一棵可下钻的行业树，满足：

1. **全量瓜分**：宇宙内每只股票恰好落入一个叶子行业；无法归属的进 quarantine，不进树聚合。
2. **可扫描**：首页约 **12–14** 个主题桶；桶内 L2 数量可控，轮动轴尽量不互相淹没。
3. **可维护**：成分归属跟申万走；主题分组是可改配置，不是第二套瓜分。
4. **可下钻**：叶子列表支持过滤排序，无需单独维护「核心池」名单。

## 2. 决策摘要

| 决策 | 选择 |
|------|------|
| 成分归属真相 | **申万行业分类 2021 二级** |
| 主题导航层 | **自研 L1**（14 个桶；由趋势动物 10 桶拆「消费」「工业」而来） |
| L1 灵感来源 | 趋势动物主题粒度，**不复制**其自定义 L2 |
| `core_pool` | **不建实体**；L2 下钻 = 过滤视图 |
| 申万一级 | 不作为产品树节点；仅作数据源旁注 |
| 多归属 / 主题标签 | MVP 不做；一只股一个叶子 |
| 配置权威源 | **Git 内 YAML**；DB 为某 `map_version` 的导入投影 |
| 展示合并 | 可选 `display_group`；**永不**改变 `stock→sw_l2` |

## 3. 树结构

```text
A股宇宙
├── L1 自研主题桶（14）         ← 首页扫描行（有成员闭包，可聚合）
│   └── L2 申万二级             ← 成分归属叶子 / 下钻入口
│       └── 个股                ← 过滤视图（非 ST、成交额排序等）
├── （可选）display_group       ← 仅 UI 折叠，如银行五二级收一行
└── quarantine                  ← 无有效 sw_l2 的标的；不进 L1/L2 聚合
```

### 3.1 层级职责

| 层 | ID 形态 | 职责 | 谁维护 |
|----|---------|------|--------|
| L1 | `l1_*` 稳定 slug | 主题分组、首页扫描、成员闭包 | 本产品 YAML |
| L2 | 申万二级代码（6 位） | 个股归属、行业节点、下钻 | 申万 + 数据商同步 |
| display_group | `dg_*` | 可选 UI 折叠 | 本产品 YAML（可选） |
| 个股 | `ts_code` | 行情与指标 | 行情源 |

**禁止**：用自定义 L2 名覆盖申万二级归属码。展示合并只用 `display_group`。

### 3.2 L1 聚合契约（分类树必须提供）

每个启用的 L1 **必须**具备成员闭包：

```text
members(L1) = ∪ members(sw_l2)  for all sw_l2 mapped to that L1
```

- 首页可以把 L1 当作扫描行：指标公式另开指标 spec，但 **成员集由本树唯一定义**。
- 禁止「L1 = 无成员的纯标签」。
- Tree API 必须返回：每个 L1 的子 `sw_l2_code` 列表，以及成员计数（见 §5.3）。

## 5. 宇宙、归属、下钻与计数

### 5.1 A 股宇宙（MVP）

**计入宇宙**：沪市 + 深市 的 A 股（主板、创业板、科创板），含尚未盈利等特殊挂牌，只要有有效 `ts_code` 与行情主键。

**不计入宇宙（MVP）**：北交所、B 股、退市整理期标的、已退市代码。

宇宙变更须发新 spec 修订或 `map_version` 说明；实现不得静默扩大。

### 5.2 归属链路

```text
stock in universe
  → sw_l2_code（申万2021二级，数据商同步）
      → 有效：l1_id = map(sw_l2_code)
      → 无效/空：quarantine（不进任何 L1/L2 聚合）
```

- 同步频率：每个交易日至少一次。
- **发布门禁**：对「宇宙 ∩ 应有归属」的标的，`unmapped_count` 必须为 0 才可把该映射/数据日标为生产就绪；IPO 未分配允许短暂 quarantine，但须进 ops 指标并设告警阈值（默认：连续 3 个交易日未归属则告警）。
- 历史按日归属快照：MVP 不做。

### 5.3 成分数语义（API 必出两套）

| 字段 | 含义 |
|------|------|
| `members_total` | 该 L2（或 L1 闭包）在宇宙内、且 `sw_l2` 有效的成分数（**含** ST / \*ST） |
| `members_tradable` | 默认交易视图：排除 ST/\*ST，且排除停牌（见下） |

ST 判定：优先用数据商 **ST 标记字段**；无字段时再用证券简称匹配（含 `ST`、`*ST`）。退市整理不在宇宙内，故不计。

**L2 指数/聚合默认宇宙** = `members_tradable` 对应集合（与下钻默认一致）。若指标 spec 要用全量，须显式声明。

### 5.4 下钻列表（替代 core_pool）

| 参数 | MVP 默认 | 说明 |
|------|----------|------|
| 宇宙 | 该 `sw_l2_code` ∩ 本 spec 宇宙 | |
| `exclude_st` | `true` | |
| `exclude_suspended` | `true` | **MVP 依赖**：行情源必须提供停牌标记；否则该版本不得宣称生产就绪 |
| `sort` | `turnover_1d` 降序 | 备选：`turnover_5d_avg`、`mv` |
| 分页 | `limit` + `offset` | `limit` 可选作精简模式，不落库 |

响应须带 `filters_applied`（实际生效的过滤项列表）。

**不创建** `core_pool` / 人工成分覆盖表。

### 5.5 L2 排序

每个 L1 下 L2 的默认展示序：映射表中的 `sort_order`（整数）；未填时回退为 `sw_l2_code` 升序。首页若按温度/RS 排 L2，属于指标层，覆盖展示序。

## 6. 数据模型（逻辑）

### 6.1 权威配置（Git）

```text
config/taxonomy/
  l1_buckets.yaml          # l1_id, name, sort_order, enabled
  sw_l2_to_l1.yaml         # map_version 元数据 + 每行 sw_l2_code → l1_id, sort_order
  display_groups.yaml      # 可选；MVP 至少提供银行折叠示例
```

- **Canonical = YAML**。MVP 无管理端写库改映射。
- 发布流程：改 YAML → CI 覆盖校验 → 导入 DB 为新 `map_version` → 切换 `active`。

### 6.2 运行时表

```text
taxonomy_map_version
  version PK              -- 如 2026.09.29.1
  status                  -- draft | active | retired
  sw_dict_label           -- 如 SW2021
  note
  created_at
  activated_at null

l1_bucket
  version FK
  l1_id
  name
  sort_order
  enabled
  PRIMARY KEY (version, l1_id)

sw_l2
  sw_dict_label
  sw_l2_code
  sw_l2_name
  sw_l1_code              -- 旁注
  sw_l1_name
  PRIMARY KEY (sw_dict_label, sw_l2_code)

l1_sw_l2_map
  version FK
  sw_l2_code
  l1_id
  sort_order
  PRIMARY KEY (version, sw_l2_code)

l2_display_group            -- 可选
  version FK
  group_id                  -- 如 dg_banks
  l1_id
  name                      -- 如 银行
  sort_order
  PRIMARY KEY (version, group_id)

l2_display_group_member
  version FK
  group_id
  sw_l2_code
  PRIMARY KEY (version, group_id, sw_l2_code)
  -- 约束：成员的 l1_id 必须等于 group.l1_id；不改变 stock→sw_l2

stock_sw_l2
  ts_code PK
  sw_l2_code null           -- null = quarantine
  as_of_date
  in_universe bool
```

同一时刻至多一个 `taxonomy_map_version.status = active`。Tree API 默认读 active；允许 `?map_version=` 钉住历史版本。

### 6.3 MVP 推荐 display_group

| group_id | 名称 | l1_id | 成员 |
|----------|------|-------|------|
| `dg_banks` | 银行 | `l1_finance` | 480200–480600 |

其它折叠后续按需加；不加也不阻塞树。

## 7. API / 查询契约（逻辑）

| 能力 | 输入 | 输出 |
|------|------|------|
| 行业树 | 可选 `map_version` | active（或指定）版本下 L1 列表；每项含 L2 子节点（代码、名称、`sort_order`、`members_total`、`members_tradable`）；可选嵌入 `display_groups` |
| L2 成分 | `sw_l2_code`, filters, sort, limit, offset | 个股列表 + `filters_applied` |
| 个股定位 | `ts_code` | `{ in_universe, sw_l2_code\|null, l1_id\|null, quarantine: bool, names… }` |
| 健康度 | 无 | `{ unmapped_count, universe_size, active_map_version }` |

过滤器枚举：`exclude_st`、`exclude_suspended`、`sort=turnover_1d|turnover_5d_avg|mv`。

## 8. 明确非目标

- 趋势动物自定义 L2 与成分逆向  
- `core_pool` / 人工精选成分表  
- 多标签主题概念股  
- ETF / 宽基 / 「关联品种」树（另开 spec）  
- 温度、RS、右侧、节气等**公式**（但本树必须提供 L1/L2 成员闭包供其使用）  
- 申万三级下钻  
- 北交所（MVP）  
- 管理端在线改映射  

## 9. 演进规则

1. **改 L1 桶 / 映射**：改 YAML → 新 `map_version` → 校验 → 切 active；禁止原地覆盖唯一活映射。  
2. **申万字典变更**：更新 `sw_l2` 字典标签/内容；新二级必须进入某版本映射，否则不能 active。  
3. **继续拆桶**：仍只改映射与 `l1_bucket`，不改 `stock→sw_l2`。  
4. **展示合并**：只动 `l2_display_group*`。  
5. **回滚**：把目标版本 `status` 设为 active，原 active 设为 retired。

## 10. 验收标准

1. 对 active 版本：映射覆盖当前申万字典全部二级，无一对多、无遗漏；`count` 三者相等（不写死 134）。  
2. 基线夹具：SW2021 下本 spec §4 合计 134，CI 用夹具锁定直至主动升字典。  
3. 宇宙内抽样个股可解析到唯一 `(sw_l2_code, l1_id)`，或明确 `quarantine=true`。  
4. L2 下钻默认排除 ST 与停牌；响应含 `filters_applied`；无 core_pool 表。  
5. 行业树返回 14 个 L1；每个 L1 含非空子 L2 列表与两套成员计数。  
6. `map_version` 可钉住；切换 active 不改 YAML 历史。  
7. Canonical 映射仅来自 Git YAML 导入。
