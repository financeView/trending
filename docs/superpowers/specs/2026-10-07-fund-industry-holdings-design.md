# 公募基金行业持仓追踪：设计意图与实现思路

这项功能把公开披露的公募基金股票持仓转换成可按申万 2021 行业比较的汇总快照。设计重点是留下可复核的行业级结果和覆盖说明，而不是保存庞大的逐基金、逐股票原始持仓明细。

## 设计思路

计算入口由 `scripts/run_fund_industry.py` 统一调度。手动运行指定仓库一级行业与其下属申万二级行业；季度全量运行处理完整的 14 个一级、134 个二级行业。程序读取 CNINFO 按股票汇总的公开持仓市值，并取得申万行业分类历史，按报告期当日有效的分类映射股票；三级分类归并到二级，再按仓库行业树汇总一级行业。抓取或校验失败时终止，不发布旧数据伪装的新结果。

比例的分母固定为报告期内成功映射至仓库行业树的沪深 A 股持仓市值，不是基金净资产或全部资产。报告另列未映射、仓库范围外证券和映射覆盖率，避免把分类不完整的数据误读为完整基金仓位。季度报告披露范围本身有限，尤其一季报和三季报常见的前十名持仓汇总，结果只代表源数据实际披露内容。

## 计算后会保存什么

默认输出目录为 `reports/fund-industry/`。手动单行业运行生成 `YYYYMMDD__一级行业ID__二级行业代码.json` 和对应的 `.md`：JSON 保存报告期、生成时间、数据源及版本、分类口径、所选行业、市值汇总、占比、覆盖统计和解释限制；Markdown 提供可读汇总。手动运行不会更改全行业历史库或趋势图。

全行业季度运行生成 `YYYYMMDD__ALL__ALL.json` 与 `.md`，并维护 `history.json` 和 `trend.html`。历史库按报告期保存 134 个二级行业的持仓市值、占映射沪深 A 股持仓比例、占所属一级行业比例，以及报告类型、披露说明和覆盖统计；相同报告期重跑会替换旧记录，按日期排序，不重复追加。不同分类版本或占比分母不兼容时拒绝混写。

GitHub Actions 将本次生成的 JSON 和 Markdown 上传为保留 90 天的 artifact，并把 Markdown 加入运行摘要。全行业运行的 artifact 还含 `history.json` 和 `trend.html`。工作流的提交步骤只 `git add` 本次 JSON、Markdown；若为全行业运行，也提交历史 JSON 和趋势 HTML。文件无变化时不产生提交；发生错误时不会提交。原始 CNINFO 行仅在内存中处理，不提交或持久化；不保存逐只基金持仓，也不建设数据库。

工作流提交到触发本次运行的分支，不会自动合并到 `main`。按功能隔离要求，文档和后续计算结果应留在 `feat/fund-industry-holdings`。不过 GitHub 要求 `schedule` 与 `workflow_dispatch` 的工作流文件存在于默认分支；因此在该功能仍仅位于开发分支、未进入默认分支时，这两个 GitHub 触发入口不可用。本文档提交本身不会启用或执行 Actions。
