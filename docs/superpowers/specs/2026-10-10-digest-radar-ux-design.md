## 1. 问题

### 1.1 L1 / L2 表：状态与事件挤在一起，且用 0/1

例（Issue #2 · L2 `270200` 元件 · as_of=2026-09-30）：

| 现状列 | 值 | 用户易误解为 |
|--------|-----|--------------|
| 右侧 | `1` | 「今天刚进右侧」或不明所以的开关 |
| T | 温 | （本身清楚） |
| 温转热 | `0` | 与「右侧=1」矛盾 |
| 成分温转热 | `0` | 不知是不是「今天」、也不知和温度档的关系 |

正解：**右侧 = 是否仍处在右侧存续（跨日状态）**；**温转热 = 当日事件**（进场日 tag 或存续期温→热/沸再确认）。  
`右侧=是` + `T=温` + `今日温转热=否` = 早已进右侧、今天温档存续、今天无新触发——合理，但现状列名/0·1 让普通人读不懂。

### 1.2 Radar「T\*」14/14 全沸

现实现：`_hottest_t` = 该 L1 下个股 `T` 的**最高档**（有一只沸 → 整行沸）。  
2026-09-30 实测：14 个 L1 的 stock-max 全是「沸」，而同日 `daily_l1.T` 为凉/平/温（无沸）——与各 L1 Issue「L1 自身」一致、也符合偏冷体感。

Spec B §5.2 曾**有意**保留截面 `T*` 并脚注「非 L1 同引擎」；落地后证明：脚注挡不住误读，战场总览被极值个股涂满「沸」。

## 2. 目标

1. L1 自身 / L2 扫描：**状态用是否、事件标「今日」、成分密度列名可读**；并补一列成分温度热度密度。  
2. Radar 按 L1：**主温度列与「L1 自身」同引擎**（读 `daily_l1.T`），消灭「全沸」假战场。  
3. 不改库表形态；新密度列在渲染时对 `daily_stock` 计数即可。

## 4. 口径钉死

### 4.1 L1 自身 / L2 扫描表头（替换）

**旧：**

```text
| T | … | 右侧 | 节气 | 温转热 | 成分温转热 | 成交额(亿) |
```

**新：**

```text
| T | … | 在右侧 | 节气 | 今日温转热 | 今日成分温转热 | 成分热以上 | 成交额(亿) |
```

（L1 自身仍含 `l1_id` / `名称`；L2 仍含 `代码` / `名称` / `RS` / `量`——列序：在 `今日成分温转热` 与 `成交额(亿)` 之间插入 `成分热以上`。）

| 列 | 数据源 | 展示 |
|----|--------|------|
| 在右侧 | `daily_l1/l2.right_side` | **`是` / `否`**；SQL NULL → 空（禁止渲染 `0`/`1`） |
| 今日温转热 | 行上 `tag_warm_to_hot` | **`是` / `否`**；NULL → 空 |
| 今日成分温转热 | `warm_to_hot_member_count` | 非负整数；NULL → `0`（与现密度列一致） |
| 成分热以上 | 见 §4.2 | 非负整数 |

布尔辅助：`1/true/"1"` → `是`；`0/false/"0"` → `否`；其它/NULL → 空。

表下脚注（L1 Issue，紧接 L2 扫描「量」注之后或合并为一条可读注）：

```text
注：在右侧=是否仍处右侧存续（状态）；今日温转热=板块自身当日进场或温→热再确认（事件）。
成分热以上=当日成分 T∈{热,沸} 个数（按行上 l1_id / sw_l2_code 过滤，见 §4.2）。
```

「量」后放注保留。

### 4.2 `成分热以上` 计数

- **定义：** asof 日 `daily_stock` 中，归属该篮子且 `T IN ('热','沸')` 的行数（**不含**「温」）。  
- **L2 行：** `sw_l2_code = 该 L2 code`。  
- **L1 自身行：** `l1_id = 该 L1 id`（与 Radar「个股温转热」同一过滤轴；**不**改用 YAML 闭包——避免本 slice 重开 Spec B「允许不一致」战役）。  
- **不落库**；每次 render 聚合。缺截面 → `0`。

与「今日成分温转热」对比（钉死，允许同时非零且互不推导）：

| 列 | 计的是 |
|----|--------|
| 今日成分温转热 | 成分 `tag_warm_to_hot=1`（当日事件） |
| 成分热以上 | 成分当前温度档 ≥热（状态截面） |

### 4.3 个股表（L1 Issue 内）

- 「今日温转热（个股…）」表头 **`右侧`→`在右侧`**，值 **`是`/`否`**（同一 `_fmt_yn`）。  
- 「右侧存续 Top」**无**右侧布尔列（已是存续子集），本 slice 不改其表头。  
- 不改筛选语义（仍按 `tag_warm_to_hot` / `right_side`）。

### 4.4 Radar「按 L1」

**旧：**

```text
| L1 | l1_id | T* | 个股 | 右侧 | 右侧占比 | 个股温转热 |
```

**新：**

```text
| L1 | l1_id | T | 个股 | 右侧个股 | 右侧占比 | 今日个股温转热 |
```

| 列 | 口径 |
|----|------|
| **T** | `daily_l1.T`（`code=l1_id`，`trade_date=asof`）；无行或 T NULL → 空。**禁止**再用个股最高温。 |
| 个股 / 右侧个股 / 右侧占比 / 今日个股温转热 | 仍按 `daily_stock.l1_id` 截面（人数与占比）；「右侧个股」仅为表头更名，语义=原「右侧」计数 |
| 排序 | 不变：右侧占比 ↓，今日个股温转热 ↓，`l1_id` |

脚注替换为：

```text
T = daily_l1 同引擎温度（与各 L1 Issue「L1 自身」一致）；
右侧个股 / 今日个股温转热 = 个股截面（按 l1_id）。
L1 闭包「今日成分温转热」见各 L1 Issue。
```

### 4.5 Radar「总览」一行

可选更名（本 slice **做**）：

```text
- 个股数=N 右侧个股=R (p%) 今日温转热=H
```

数字口径不变。

## 6. 实现要点（给 plan）

1. `digest.py`：`_fmt_yn(v) -> str`；L1/L2/个股布尔列走它。  
2. `_count_members_hot_plus(conn, td, *, l1_id=None, sw_l2_code=None) -> int`。  
3. Radar：`LEFT`/点查 `daily_l1` 取 `T`；删除按 L1 聚合里的 `_hottest_t(...)`。  
4. 单测：  
   - 表头字符串更新（`test_l1_digest` / `test_digest_rs_vol`）  
   - `right_side=1` → 单元格 `是`，不得出现 `| 1 |` 充当在右侧  
   - 夹具：两只成分 T=热/沸/温 →「成分热以上」只计热+沸  
   - Radar：夹具 `daily_l1.T=凉` 且成分含沸 → 按 L1 的 `T` 为凉，不为沸  
5. 不要求本 slice 改 Actions；本地/CI 单测绿即可合入。
